# Safe under Belfry

## Goal

Peal works and stays safe when Belfry runs it without the worker's gh login, and no session can grant itself consent: close opens its pull request through pr_create and the reads degrade without a login, every other gh call is listed or refuses with the reason, a filing from the control plane never fails after the human accepted it, merge: auto is the human's alone, a fabricated remote ref proves nothing, the contract template is complete, shape-only pushes cannot turn text from outside into consent, and the trusted-App issues storage is complete. Its release unblocks Belfry #42; #671 follows once the issues storage records through Belfry (Contract kept).

## Acceptance criteria

- Under a session with no gh login (a `gh` that fails authentication), `close finish`
  ends with the pull request opened through `pr_create` with the same title, body and
  draft state, and `peal list` and `peal board` answer with the pull request state
  marked unknown (0176).
- Every other gh call Peal makes is listed for Belfry or has a path, a test keeps the
  list complete, and the writes that need a login refuse up front with the reason
  (0203).
- A text with no heading is filed by `peal create --title` under that title, so a
  control-plane proposal that passed its dry run never fails at filing (0204).
- A claim copy carrying `merge: auto` does not make the board print `merge`; `peal
  record`, `revise` and `comment` refuse a text that adds it (0177).
- The pre-push gate refuses a locally made merge onto main, also with a fabricated
  `refs/remotes/*` ref (0178).
- The `peal init --stage belfry` template names `apply_kinds`, `max_code_jobs` and
  `never_auto_merge` with `.peal/**`, and Peal's own contract does (0179).
- A direct revise push that drops `origin: outsider`, adds `merge` or fills `## Plan` is
  refused; a stranger's issue whose body holds `## Plan` reads as `PLAN required` (0180,
  0161, 0122).
- `/peal:idea` under a control plane on the issues storage files its fields as labels
  and a milestone, and `/peal:setup` lists a trusted App's issues as candidates (0173,
  0175).
- `docs/security.md` describes each of these with its test.
