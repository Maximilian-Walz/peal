# Ready for newcomers

## Goal

A newcomer, a heavy user with their own setup and an AI agent each understand, try and adopt Peal from its docs.

## Acceptance criteria

- The README's first screen says what Peal is, needs and costs, and that the default
  plan mode may start the build without showing the plan (0191).
- `docs/adopting.md` exists with both parts and the back-out list, `docs/migrating.md`
  is gone and no link to it is dead (0192); the troubleshooting page and the FAQ exist
  and are linked (0193); `AGENTS.md` and a real example transcript exist and the
  manifests carry the new description (0194); A1 to A13 are fixed and `docs/design.md`
  has no issue-numbered history (0195).
- After a write to main a clean checked-out main is fast-forwarded, else one line says
  it is behind, and `peal doctor` reports it (0196).
- Empty answers say so, `peal --help` fits one screen, the unknown-command message names
  the running Peal, and doctor, release, migrate and create messages say what to do
  (0197); doctor flags a task whose heading disagrees with its id (0197).
- `close finish` with `pr.host: none` ends with the pushed branch and the compare URL
  (0198); `peal import` files a TODO list, issues or a CSV once (0200); `peal status`
  prints one screen (0201).
- `peal record` accepts a Raw section added to a task filed without one (0134);
  set-milestone refuses clearing a milestone a `depends: milestone` needs (0140); every
  error line names its command (0228); a repeated `apply` batch files nothing twice
  (0226).
- Every example on the new pages passes `tools/docs.test.sh`.
