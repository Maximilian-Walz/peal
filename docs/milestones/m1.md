# Safe in public

## Goal

Peal is public: it runs shell on its users' machines, installs git hooks in their
repositories and feeds issue text to sessions. This milestone makes that safe to rely on,
and says how to report it when it is not: a threat model, hostile input refused or
quoted, hooks and a launcher that never run what a repository ships, and a CI whose
supply chain is pinned.

## Acceptance criteria

- `SECURITY.md` and `docs/security.md` exist, and private vulnerability reporting is on (0038).
- A hostile-input harness runs every command with hostile values in CI, and `shellcheck`
  is clean (0039).
- Harnesses show that the git hooks and the launcher execute nothing from the repository,
  and that `peal init --remove` leaves nothing behind (0040).
- Every action in the workflows is pinned by SHA, Dependabot and Scorecard are configured,
  and each job's permissions are minimal (0041).
