# Contract kept

## Goal

Peal follows the contract decisions the control plane makes in its Belfry on Peal milestone, and its CI proves it: the issues storage records through the control plane's task_record so the login can be hidden, the published fixtures checked in CI, detection by the tools offered rather than an environment variable, one defer path that ends by calling the control plane's tool, one rule for a filed idea's milestone, the guide holding the with-Peal lines the contract drops, and recorded fields the board sees at once. Its release lets the control plane hide the gh login for good (its #671).

## Acceptance criteria

- On the issues storage under the control plane, `peal record` and the agreed fields go
  through `task_record` when it is offered, and `peal work` on such a task succeeds with
  no gh login (0227).
- Peal's CI reads the control plane's published fixtures and fails on a `.belfry.yml`
  its checker refuses (0202).
- `/peal:idea` and `/peal:close` detect the control plane the same way, by its tools
  (0222).
- `/peal:defer` under the control plane leaves one record the control plane reads
  (0223).
- A filed idea's milestone is decided once (0224).
- `docs/guides/belfry.md` names no command that does not exist, and `/peal:comment`
  takes the origin from its argument (0225).
- `peal record` pushes the claim branch and `peal apply` prints no shell error for a
  hostile title (0142, 0155).
